# Local-first result access

## Current implementation

In Results, open **Local folder · browser-only analysis** and select one
experiment folder or a parent directory containing experiment folders. The
browser reads the selected File objects directly, without using a result-upload
endpoint. The existing Results workbench receives an in-memory projection.
Workspace results and the browser folder are separate sources; use
**Use Studio workspace instead** to return to the original workflow.
Re-select the folder to obtain current file contents. Selecting a folder does
not grant continuous filesystem access. Reloading the page requires selecting
the folder again.

Read allowlist: manifest.json, final_metrics.json, validation_history.json.
Missing metrics remain missing; malformed runs are skipped with reasons.
The adapter bounds recognized directories and summary bytes; weights, datasets,
client NPZ files and HDF5 files are not read. The optional logit file is read
only on explicit request. No result contents are sent to the Python server,
GitHub, cookie storage, localStorage or IndexedDB.

Multi-seed summaries automatically use all distinct unambiguous compatible seeds.
If multiple runs have the same seed under one exact condition, that seed is
excluded with an explanation rather than overweighted or arbitrarily selected.
Single experiment inspection remains available. Baseline comparisons use
the matched seeds; sensitivity comparisons use common matched seeds across levels.

Local condition keys are recomputed from the selected manifests, not imported
as trusted claims. They use canonical JSON equality within the local source;
these keys are not interchangeable with Python SHA-256 cohort keys. Metadata
matching is not independent verification of weights, data or execution.

## Logits versus recorded summaries

The standard Runtime currently computes softmax probabilities from model logits
and saves test metrics and validation summaries. Its trajectory.h5 stores
weights, updates and other evidence, not raw test logits by default. No
historical logits can be recovered from a confusion matrix or final scores.

The browser reader also supports a proposed explicit, labeled portable file
named test_logits.json in the experiment directory:

```json
{"schema_version":1,"split":"test","classes":["benign","dos"],"labels":[0,1],"logits":[[1.5,-0.5],[-0.1,0.9]]}
```

Illustrative data only. Labels are zero-based class indices, and columns must
match the audited class order exactly. The reader calculates argmax accuracy,
confusion counts, average maximum softmax confidence and numerically stable
unclipped negative log likelihood. These are separate descriptive calculations;
they do not replace recorded metrics or establish evaluation population
identity. The raw file is not automatically generated by Runtime. A future
explicit export must include run, split, round, population and model identity;
personalized evaluation needs its own contract. HDF5 reading is a separate task.

## Browser-only hosting roadmap

The independent local-results.js adapter has no network or DOM dependency.
analysis-core.js provides reusable statistical functions. The current Studio
shell still uses Python APIs for catalog, configuration validation and export;
it is not yet a standalone GitHub Pages build.

For the static viewer, share the Results rendering layer with a browser-only
bootstrap, eliminate backend requests, use relative asset URLs, and enforce
a restrictive Content Security Policy (including connect-src 'none') where
compatible with the deployment. Test with outbound requests blocked.
Browser compatibility fallback is the directory file input. In supported
browsers, a future opt-in File System Access handle may be stored in IndexedDB
and reopened after explicit permission checks. Do not persist experiment files
or logits in cookies. Keep preference storage separate from evidence storage.
GitHub Pages should serve application assets only, never user experiment data
or SSH credentials. Actual study sharing is a separate explicit export/import
feature; no automatic publication.
