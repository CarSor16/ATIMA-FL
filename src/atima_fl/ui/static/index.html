From profile to comparison
ATIMA: Adversarial Testing Infrastructure for Model Aggregation. FL denotes Federated Learning.
  1. Choose components, data, seed and budget. Displayed parameters come from component files.
  2. Validate the configuration and export the plan. Saving does not start training.
  3. Transfer the plan to the cluster. Request a real GPU and the specified CPUs in New Batch Job.
  4. Run bash run_cluster.sh preflight. After verification, run bash run_cluster.sh train.
  5. Complete clean first, then its paired attack. Export useful metrics and artifacts for analysis.
  6. Analyze with atima analyze --clean ... --attack ... --output .... For multiple seeds use atima statistics.
Modes and topology
Simple mode shows essential choices. Advanced exposes hyperparameters, malicious IDs, server assignments, resources and stopping; changing modes preserves all values. Client/server IDs start at 0. The attack window includes both endpoints and ends before the next round. Disabling exports a clean profile without malicious clients. One server aggregates all clients; multiple servers aggregate groups and a coordinator combines deltas by original sample mass. Defenses run inside groups. Local placement uses worker processes. Physical placement requires one Slurm node per aggregation server and verifies distinct worker hostnames. Client updates are routed through the coordinator and shared job files; this transport provides no network or privacy isolation. Physical placement requires verification on the target cluster.
Adding a component
A Python file in its category folder, with PLUGIN, parameters and hooks. Use atima ui --plugins plugins to load external components. Removing a file explicitly rejects profiles that selected it.
Interpretation
Local checks establish fixture software behavior. Performance, attack efficacy and GPU use require cluster experiments. Rounds are not independent statistical replicates.
